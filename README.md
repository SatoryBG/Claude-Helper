# Claude-Helper

Personal plugins for [Claude Code](https://code.claude.com), published as a single marketplace. Add the repo once per machine, then install and update plugins with one command.

## Plugins

| Plugin | Version | What it does | Dependencies |
|---|---|---|---|
| [md-to-html](plugins/md-to-html/README.md) | 1.0.1 | Documents as an MD + HTML pair: Claude writes only Markdown, the HTML is generated by pandoc at zero token cost. Two styles (report, tech), report components, automatic regeneration on edit, multilingual UI (English, Bulgarian, extensible). | pandoc 3.1.10+ (installed by `/md-to-html:install`) |
| [web-research](plugins/web-research/README.md) | 1.1.0 | Token-efficient web research in Haiku subagents with explicit limits: a fast WebSearch/WebFetch researcher and a real-browser researcher (Playwright, Chromium) for JavaScript-heavy, interactive or login-only pages. Rules are added to every session; optional enforcement blocks direct web tools in the main conversation. | none for the researcher; Node.js 20+ and Chromium for the browser-researcher (installed by `/web-research:install`) |
| [satory-devteam](plugins/satory-devteam/README.md) | 1.0.0 | A team of AI agents that takes a small software project from idea to production: analyst (SPEC), architect (architecture, UI guide, plan), then per task Dev, Code Reviewer, QA (Playwright), UI reviewer (screenshots + axe), Security and Docs, with guards enforced by code, an append-only journal and local Docker staging/prod. You approve the SPEC, the plan and each production release. | git, gh, python3 3.10+, Docker, Node.js, Playwright Chromium; optional .NET SDK, gitleaks, semgrep (installed by `/satory-devteam:setup`) |

## Installing on a new machine

In Claude Code:

```text
/plugin marketplace add SatoryBG/Claude-Helper
/plugin install md-to-html@satory-claude-helper
/plugin install web-research@satory-claude-helper
/plugin install satory-devteam@satory-claude-helper
```

Install only the plugins you need. Then install the plugin's dependencies, if it has any (for md-to-html: `/md-to-html:install`; for the web-research browser agent: `/web-research:install`; for satory-devteam: `/satory-devteam:setup`).

The same from a terminal:

```bash
claude plugin marketplace add SatoryBG/Claude-Helper
claude plugin install md-to-html@satory-claude-helper
claude plugin install web-research@satory-claude-helper
claude plugin install satory-devteam@satory-claude-helper
```

> If the repo is private, git on the machine needs access to GitHub (for example `gh auth login` or an SSH key). A path to a local clone works too: `/plugin marketplace add /path/to/Claude-Helper`.

## Updating

```text
/plugin marketplace update satory-claude-helper
/plugin update md-to-html@satory-claude-helper
/plugin update web-research@satory-claude-helper
/plugin update satory-devteam@satory-claude-helper
```

Claude Code only sees a new version when the plugin's `version` has been bumped.

## Repository layout

```text
Claude-Helper/
├── .claude-plugin/
│   └── marketplace.json        # catalog: the plugins and where they live
├── plugins/
│   └── <name>/
│       ├── .claude-plugin/
│       │   └── plugin.json     # name, version, description
│       ├── README.md           # plugin documentation and changelog
│       ├── skills/<skill>/SKILL.md
│       ├── hooks/hooks.json    # optional
│       ├── agents/             # optional
│       └── commands/           # optional
├── CLAUDE.md                   # rules for Claude when working on this repo
└── README.md
```

## Adding a plugin

1. Create `plugins/<name>/` with `.claude-plugin/plugin.json` and whatever `skills/`, `hooks/`, `agents/` or `commands/` it needs.
2. Add an entry to the `plugins` array in `.claude-plugin/marketplace.json`:
   ```json
   { "name": "<name>", "source": "./plugins/<name>", "description": "...", "version": "1.0.0" }
   ```
3. Write `plugins/<name>/README.md` and add a row to the table above.
4. Validate:
   ```bash
   claude plugin validate . --strict
   claude plugin validate plugins/<name> --strict
   ```
5. Commit and push. On other machines: `/plugin marketplace update satory-claude-helper`, then `/plugin install <name>@satory-claude-helper`.

Conventions:

- Everything is in English. Localization lives in data files, not in code.
- Bump `version` in both `plugin.json` and `marketplace.json` on every change.
- Reference plugin files in hooks via `${CLAUDE_PLUGIN_ROOT}`.
- Run scripts as `bash <path>` instead of relying on the executable bit.
